# Changelog

Milestones are defined in `CLAUDE.md`. Each was planned, approved and merged as its own
pull request.

## M10: presentation

- Example reports in `examples/` (phishing email as Markdown and HTML, shortcut lure,
  macro document), regenerated by `scripts/make_examples.py` from the synthetic fixtures.
- A screenshot of the HTML report at the top of the README.
- `Dockerfile`: every analyzer and the oscrypto fix, unprivileged user, meant to run with
  `--network none`. CI builds it and triages a synthetic email offline.

## M9: damaged-input testing

- `tests/test_fuzz.py`: every fixture damaged in seeded ways (truncation, bit flips,
  extreme size fields, duplicated, removed and zeroed chunks), run through the pipeline
  and all three writers; fails on any crash or any silent check failure. 4 rounds per
  fixture in CI, `UNOPENED_FUZZ_ROUNDS` for more. 60 rounds (about 1,000 files) pass.
- ZIP: a damaged or missing central directory no longer stops the archive analyzer;
  members are recovered from local file headers (stored and deflated), reported PARTIAL
  with a MEDIUM `archive.damaged_directory` finding. One damaged member no longer stops
  the others (pyzipper's own exception types were escaping).
- TLSH: input with too little variation is listed under Not checked instead of failing
  the analyzer.

## M8: HTML report and folder mode

- `--format html` writes a self-contained page built from the Markdown report (same
  content, already defanged): verdict banner, folding sections, severity colors, no
  scripts, a Content-Security-Policy that blocks all network loads. `--format all`
  writes md, json and html.
- `unopened triage FOLDER --out DIR` triages every file under the folder and writes
  `summary.md` (and `summary.html`), worst verdict first.

## M7: email input

- **Email analyzer** for `.eml` (identified from content, not the extension) and Outlook
  `.msg`: sender and reply-to checks, SPF/DKIM/DMARC from the topmost
  `Authentication-Results` header, look-alike and punycode domains against an editable
  brand list (`data/brands.toml`), link-text mismatches, forms, raw-IP and script links.
- **Attachments** are extracted with the bounded member writer and triaged recursively,
  including attached messages. An attachment with a runnable extension counts toward
  V-MAL-06; emails take the most severe verdict of their members (V-MAL-09, V-SUS-02,
  V-CNA-04).
- **Hunt queries** for other deliveries of the same message: Defender for Office 365
  `EmailEvents` and `EmailUrlInfo`, the Splunk CIM Email data model, and ECS `email.*`.
- Analyzers can now apply to a subtype (`"ole:outlook"`), so `.msg` files keep the Office
  checks and also get the email analyzer.
- Quoted-printable soft line breaks are removed before raw string extraction from an
  email, so domains are not cut in half.

## M6: hardening without the analysis VM

- **CI**: GitHub Actions runs `ruff`, the test suite and a check that
  `docs/verdict-rules.md` matches the rules, on Python 3.11 and 3.13, with every optional
  analyzer installed.
- **capa**: the parsed rule set is reused from capa's on-disk cache (it was written but
  never read back), and a run that times out falls back to file-level rules only. The
  report then marks capa PARTIAL and lists function-level capabilities under Not checked.
  Analyzers can declare such a fallback in general; a fallback never reports OK.
- **FLOSS** (optional `floss` extra): decoded, stack and tight strings for PE files,
  recovered by emulation in vivisect like capa. Shown in the report and searched for
  indicators, but kept out of the verdict until a benign-corpus rerun.
- The validation harness labels capa fallbacks `capa:timeout-fallback`.

## M5: validation on real samples

RPISEC course labs, two MalwareBazaar holdout sets and two benign corpora, run in an
isolated VM. Behavior patterns, many detection and false-positive fixes, each with a
synthetic regression test. Results and method in `docs/validation.md`.

## M4: reputation and hunt queries

Opt-in hash-only lookups at MalwareBazaar and VirusTotal (`--reputation`), and hunt
queries for Splunk, Microsoft Sentinel / Defender and Elastic.

## M3: archives, scripts, PDF, verdicts

Bounded recursive extraction of ZIP, 7z and ISO; text-only script deobfuscation; PDF
JavaScript, actions and attachments; documented verdict rules.

## M2: capa, YARA, Office, LNK

capa capabilities with ATT&CK mapping, YARA with user rules, Office macro and
template-injection analysis, shortcut analysis.

## M1: the tool

CLI, type identification by content, hashes, PE basics, Authenticode, strings and
indicators, defanged Markdown and JSON reports.
